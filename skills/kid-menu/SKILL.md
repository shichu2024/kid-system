# kid-menu

> 个性化菜单推荐引擎。**过敏原绝对排除，优先级高于一切其他考量。**

## ⚠ 执行硬约束

1. **安全滤网顺序不可变**：过敏排除（档案 allergies + 规则库饮食禁忌）→ 窒息风险排除（<3 岁，见 `safety-rules.json → choking_hazards`）→ 规则过滤 → 其他偏好。**任何一步命中的食材/菜品直接弃用，不用「减量」替代**
2. **禁用清单硬编码**：≤12 月禁蜂蜜；1 岁内辅食不加盐糖；3 岁内禁整颗坚果/果冻/整粒葡萄/爆米花/硬糖
3. **分龄强制对齐**：≤36 月必须按 `feeding-stages.json` 对应阶段的质地（泥糊/碎末/小块）与单餐量选菜；>36 月按 `nutrition-standards.md` 对应年龄段
4. **护理模式**：当日/次日 `health_status=ill` → 强制 `mode=light`（清淡易消化），并在菜单标注护理模式说明
5. **周期均衡**：读取近 3 天 `02_plans/` 与 `01_journal/` 的菜品记录，**同一菜品不得在 3 天窗口内重复出现**（批量模式滚动窗口）
6. **每菜完整输出**：食材清单（用量精确到克/勺）+ 制作步骤 + 营养亮点 + 喂食注意（过敏提示/咀嚼要求）+ **2-3 种替换方案**——五项缺一不可
7. **免责声明**：菜单末尾附「营养建议仅供参考，不能替代专业医疗建议」

## 1. 何时调用

- 「今日菜单」「明天吃什么」→ 生成
- 「把午餐换成清淡的」「替换食材」「不吃海鲜」→ 调整
- 「生成本周菜单」「未来 3 天吃什么」→ 批量
- kid-plan 聚合时被调用（菜单节）

## 2. 输入

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `date` | 否 | 今天 | 目标日期（生成次日方案时为明天） |
| `mode` | 否 | normal | normal / light 清淡 / iron 补铁 / calcium 补钙 / quick 快手菜 |
| `days` | 否 | 1 | 批量 1-7 天 |
| `child_id` | 否 | active_child | — |

## 3. 工作流

### 步骤 1 · 上下文加载（指令优先级从高到低依次读取）

1. 档案：`allergies[]` `diet_restrictions[]` `chronic_conditions[]`（绝对项）
2. 规则库：`03_rules/rules.md` 中 active 的 diet_restriction / feeding 类条目
3. 分龄标准：重算月龄 → `nutrition-standards.md`（+ ≤36m 时 `feeding-stages.json` 阶段数据）
4. 行为数据：`tags.md` 饮食偏好 + 近 3 天日志/方案菜品记录
5. 健康模式：最近日志 `health_status`（ill → 护理模式）
6. 家庭条件：`pantry_scope[]`（常用食材优先）、`family_diet_style`

### 步骤 2 · 模式适配

| mode | 选材要点 |
|------|---------|
| light | 粥/面条/蒸蛋/蔬菜泥等易消化；忌油炸/辛辣/高纤维粗粮；蛋白以蛋/鱼/豆腐为主 |
| iron | 红肉/肝泥/强化铁米粉/配 VC 水果促吸收（≤36m 优先 feeding-stages 中 iron_rich 食谱） |
| calcium | 奶/奶酪/豆腐/深绿叶菜/芝麻酱；标注VD协同 |
| quick | ≤20 分钟可完成；一锅出/蒸煮为主；适配「做饭时」场景游戏推荐联动 |

### 步骤 3 · 选菜与过滤

1. 按「谷物 + 蔬菜 + 蛋白源 + 水果」结构组合三餐两点
2. 逐菜过安全滤网（硬约束 1-2）
3. 周期均衡：3 天窗口查重；批量模式额外输出周食材多样性统计（谷物≥3种、蔬菜≥5种、蛋白源≥4种/周）
4. 偏好加权：likes 加分、dislikes 降分（但不完全排除——搭配「少量尝试 + 替换方案」策略，尊重厌恶清单中强排斥项除外）

### 步骤 4 · 组装输出（模板：daily-menu.md + dish.md）

```
早餐 / 上午加餐 / 午餐（主食+荤菜+素菜+汤）/ 下午加餐 / 晚餐
▌今日营养重点（对照分龄标准说明本日缺口补偿，标注来源文件与年龄段）
▌备餐提示（可提前准备项、生熟分开、按月龄标注盐糖策略：≤12m「不加盐糖」/ 1-3y「少盐」）
每道菜按 dish 模板完整输出（硬约束 6）
▌免责声明
```

月龄 ≤36m：每菜额外标注「适用月龄」与质地说明。

### 步骤 4.5 · 输出回显（v1.3.2）

回复简报（无论菜单是写入文件还是内联展示）**必须包含**以下可核对内容：
1. **方案完整路径**：`02_plans/<child-id>/YYYY-MM-DD.md` 一行连续书写（批量模式逐日各列一行），不拆行不省略文件名；**一律用 vault 相对路径 + 正斜杠**——禁止输出绝对路径或反斜杠（`C:\...` ❌），无论实际写盘位置在哪
2. **方案 frontmatter 回显**：以 ```yaml 围栏附上方案文件的 frontmatter（date / child_id / age_months_at_plan / plan_type / health_mode）——**plan_type 枚举仅两个值**：`daily`（单日）/ `weekly_batch`（批量），禁止自创其他值（如 daily_menu）；health_mode 仅 `normal` / `care`
2. **安全过滤声明**：一句话点名档案中的**过敏**项与禁忌项已被排除（如「已过滤过敏原：蛋类（全菜单及替换方案零出现）」）——即使无过敏也须声明「无已知过敏」
3. **盐糖策略标注**：≤12 月龄须出现「不加盐糖」字样；1-3 岁标注「少盐」
4. **菜品完整性声明**：简报字面声明「每菜 5 要素齐全（食材用量 / 制作步骤 / 营养亮点 / 喂食注意 / 替换方案）」

### 步骤 5 · 调整流程（调整类指令）

1. 解析调整指令 → 定位受影响餐次/菜品
2. 重生成对应部分（其余保持不变），记录到方案 frontmatter `adjustments[]`（instruction + reason + date）
3. 调整原因沉淀：「连续拒绝」「食材缺货」等与偏好相关的原因 → 同步 tags.md 计数（引用 kid-journal 沉淀规则）

## 4. 输出契约

| 项 | 值 |
|----|----|
| 路径 | `02_plans/<child-id>/YYYY-MM-DD.md` 菜单节（文件不存在则创建，frontmatter 按 journal-schema plan 定义；存在则只重写菜单节） |
| 菜品完整性 | 每菜 5 要素（食材用量/步骤/营养亮点/喂食注意/替换方案） |
| 批量 | days>1 时逐日生成，日期+1 滚动均衡窗口 |
| 调整 | adjustments[] 记录完整 |

## 5. 边界

- 不推荐保健品/补剂/药膳；不确定的用量标注区间并说明
- 不输出生食（溏心蛋/刺身/未全熟肉）给任何年龄段儿童
- 家长要求的违反安全滤网的菜品（如给 2 岁孩子整颗坚果）→ 拒绝并解释，提供安全替代

## 6. 降级路径

| 场景 | 行为 |
|------|------|
| 档案缺过敏信息 | 停止生成，引导补全（kid-init ②/kid-profile） |
| 家庭食材范围极窄 | 在 pantry_scope 内组合 + 明确列出建议采购清单（≤5 项） |
| 近 3 天无日志 | 周期均衡只用 02_plans 记录；偏好只用 tags.md；说明数据局限 |
| mode 冲突（生病 + 家长要快手菜） | 护理模式优先，说明原因 |

## 7. 幂等保证

- 同日重新生成：完整替换菜单节（保留 adjustments 历史）
- 调整指令幂等：相同指令重复执行结果一致

## 8. 自检清单

- [ ] 过敏/禁忌食材逐一核对，零出现（含替换方案中的食材！）
- [ ] 回显五件套（步骤 4.5）：方案完整路径（一行连续，批量逐日）/ 方案 frontmatter（yaml 围栏，plan_type 仅 daily|weekly_batch）/ 安全过滤声明点名过敏项（无过敏也声明「无已知过敏」）/ 盐糖策略标注（≤12m「不加盐糖」）/ 每菜 5 要素字面声明
- [ ] ≤36m 质地与月龄标注齐全；窒息风险清单零命中
- [ ] 3 天窗口查重执行（列出查重依据）
- [ ] 每菜 5 要素齐全，替换方案 ≥2 种
- [ ] 护理模式正确触发（如适用）
- [ ] 营养重点对照了正确年龄段标准，并**标注来源**（nutrition-standards.md 对应表 / feeding-stages.json 对应阶段）
- [ ] 免责声明已附
- [ ] adjustments[] 已记录（调整类调用）
