# kid-rules

> 家长个性化养育标准的落地入口。**注入的知识优先级高于通用推荐，但低于且不得违反安全红线与档案过敏禁忌。**

## ⚠ 执行硬约束

1. **安全红线否决权**：与 `safety-rules.json` 冲突的规则（如「给 1 岁宝宝吃蜂蜜润肠」「多加盐有劲」）→ **拒绝注入**，解释原因并给安全替代；无商量空间
2. **过敏禁忌不可被规则覆盖**：家长试图用规则放开过敏限制（「海鲜过敏但少量试试」）→ 拒绝，引导咨询医生；档案过敏是绝对项
3. **冲突校验强制**：每条新规则必须与规则库现有 active 条目逐条比对（同类目同对象不同要求 = 冲突），有冲突必须列出双方由家长裁决，**不得静默覆盖**
4. **冲突需折中**：家长未裁决前不写入；家长给出裁决后记录到 `conflicts-log.md`（时间/双方/裁决/理由）
5. **单次 ≤10 条**：超出的部分提示分批注入
6. **条目格式合规**：每条规则含 rule_id（R001 递增）/ type / scope / priority / source / status，符合 `journal-schema.json` rule 定义
7. **生效说明强制**：注入成功后必须说明该规则影响的模块（menu/learning/games）与生效方式

## 1. 何时调用

- 「注入规则」「设定喂养要求」「我们家不吃猪肉」「按回民习俗安排饮食」→ 注入
- 「查看已注入规则」「育儿规则列表」→ 查看
- 「修改规则」「删除规则」「停用 XX 规则」「调整优先级」→ 管理
- kid-review 复盘建议经家长确认后「转化为规则」→ 注入（source 标注来自复盘）

## 2. 输入

| 参数 | 必填 | 说明 |
|------|------|------|
| 规则文本 | 注入时 | 自然语言，可含多条（≤10） |
| `rule_id` | 管理时 | 目标规则 |
| 操作 | 管理时 | edit / delete / enable / disable / reorder |
| `language` | — | 随 vault 配置 |

## 3. 工作流

### 步骤 1 · 解析

从自然语言提取规则条目，每条映射：

| 字段 | 说明 |
|------|------|
| `type` | diet_restriction 饮食禁忌 / feeding 喂养要求 / education 教育要求 / routine 作息要求 / general 通用养育 |
| `scope` | menu / learning / games（可多选；general 默认全选） |
| `content` | 规则正文（规范化表述，保留家长原意） |

解析不清（「按老家的方式带」）→ 反问澄清，不猜。

### 步骤 2 · 安全校验（硬约束 1-2）

对照 `safety-rules.json` + 档案 `allergies[]` / `diet_restrictions[]`：
- 命中红线/过敏放开 → 拒绝 + 解释 + 安全替代（如「1 岁内禁蜂蜜 → 可用果泥增甜」）
- 通过 → 步骤 3

### 步骤 3 · 冲突校验

```
对每条新规则 R_new：
  遍历 rules.md 中 active 同类规则 R_old：
    对象重叠（食材/行为/时段） ∧ 要求不同 → 冲突对 (R_new, R_old, 冲突点描述)
```

- **无冲突** → 展示解析结果 + 影响范围 → 家长确认 → 写入（rule_id 递增，priority 默认排在同 scope 末位）
- **有冲突** → 列出全部冲突对（双方原文 + 冲突点）→ 请家长裁决：
  - 二选一（新替旧：旧规则转 disabled）
  - 共存（不同对象/时段可细化共存，如「工作日不吃糖 / 周末少量」）
  - 放弃新规则
  → 裁决后写入 + `conflicts-log.md` 记录

### 步骤 4 · 生效说明

输出：规则名 + 影响模块 + 生效方式示例（如「R004 不吃猪肉 → 明日菜单的荤菜将从牛/鸡/鱼中选取」）+「立即生效：下一次方案生成自动适配」。

### 步骤 5 · 管理操作

| 操作 | 行为 |
|------|------|
| 查看 | 按 priority 排序列表（rule_id/类型/内容/范围/状态/来源） |
| edit | 修改 content/scope → 走步骤 2-3 重新校验 |
| delete / disable | delete 物理删除（记录到 conflicts-log 备注）；disable 转状态 `disabled`（保留可重启用） |
| reorder | 调整 priority 数字（越小越优先），输出新排序 |

## 4. 输出契约

| 项 | 值 |
|----|----|
| 规则库 | `03_rules/rules.md`，条目格式见 DESIGN §4.5（frontmatter 或条目块二选一，vault 内保持一致） |
| 冲突记录 | `03_rules/conflicts-log.md`（时间/双方/裁决/理由） |
| rule_id | `^R\d{3,}$` 递增，不复用已删除 ID |
| 反馈 | 注入结果 + 影响模块 + 生效说明 |

## 5. 边界

- 不注入涉及医疗治疗的规则（「发烧用偏方XX」→ 拒绝 + 就医引导）
- 不评判规则背后的养育观念（习俗类规则照常注入，只在安全红线处拦截）
- 复盘转规则同样走全流程校验（不因来源是系统建议而豁免）

## 6. 降级路径

| 场景 | 行为 |
|------|------|
| 规则文本一条里混杂多条要求 | 拆分为多条分别确认 |
| 规则与科学标准冲突但不涉安全（如「2 岁开始背古诗」vs 快乐学习理念） | 提示差异 + 采纳家长规则（优先级 2 > 3），附科学参考 |
| 规则库文件缺失 | 按 kid-init 骨架重建后操作 |
| 家长裁决「都保留」但实质互斥 | 说明不可共存原因，强制三选一 |

## 7. 幂等保证

- 相同规则文本重复注入 → 识别为已有条目，提示已存在（不重复写入）
- 管理 操作幂等（disable 已 disabled 规则 → 无变化提示）

## 8. 自检清单

- [ ] 安全校验执行：红线零放行、过敏零放开

- [ ] rule_id 递增合规、格式符合 rule schema
- [ ] 输出了影响模块与生效说明
