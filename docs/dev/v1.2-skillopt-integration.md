# v1.2 · SkillOpt 评测体系集成设计

> 状态：v1.2.0 ｜ 蓝本：quick-knowledge v1.3 SkillOpt 集成（docs/dev/v1.3-skillopt-integration.md）
> SkillOpt 是微软开源的「文本空间技能优化器」（PyPI `skillopt`，MIT），本仓库**当库用**（不注册其内部 `_ENV_REGISTRY`），只消费 `SplitDataLoader / EnvAdapter / chat_target` 等 API，与上游 registry 变化解耦。

## 1. 目标与范围

| 做什么 | 不做什么（v1.2） |
|--------|-----------------|
| Rollout + 评分 + 报告（golden case 行为回归） | optimizer train/reflect（configs 预留 `train.epochs: 0`） |
| nightly 非阻塞 CI + 手动触发 | 阻塞 PR（行为评测只参考不卡门） |
| chat 后端单轮（SKILL.md 作 system，case input 作 user） | exec 后端（真实 Claude Code 子进程写 vault 副本，预留 seam） |
| 三类 case 集：menu（22）/ journal（16）/ flow（6）+ unseen（8） | — |

## 2. 目录结构

```

├── run_eval.py            # 主入口：python bench/run_eval.py --skill menu --split test
├── run_unseen_eval.py     # 泛化探针（flat items.json，无 split）
├── repro_case.py          # 单 case 复现：python bench/repro_case.py <case-id>
├── cases/
│   ├── _schema.json       # case 自文档 schema
│   ├── menu/items.json    # kid-menu 单点（安全滤网/分龄/护理/查重/降级/结构）
│   ├── journal/items.json # kid-journal 单点（红线/异常识别/不编造/沉淀/触发）
│   ├── flow/items.json    # J1-J6 闭环端到端（零容忍 gate 语义）
│   ├── flow/fixtures/     # 每过渡一个上游产物 fixture JSON
│   └── unseen/items.json  # U1-U8 泛化探针
├── configs/
│   ├── menu-default.yaml  # split 3:1:1 · epochs 0 · gate off
│   ├── journal-default.yaml
│   └── flow-default.yaml  # split 0:0:6 全 held-out（零容忍）
├── kidsys/                # 「四件套」适配层（原 quickkb 模式）
│   ├── dataloader.py      # KidsysDataLoader(SplitDataLoader)
│   ├── adapter.py         # KidsysAdapter(EnvAdapter) 接线层
│   ├── rollout.py         # run_batch / fixture 内联 / skill 路由
│   └── scoring/           # aggregate(合取+均值) + routing/frontmatter/behavior/flow
└── reports/               # 运行产物（gitignore，仅 .gitkeep 入库）
```

## 3. 与 quick-knowledge 蓝本的差异

| 差异点 | 原因 |
|--------|------|
| 移除 polish/user_choice 机制 | kid-system 无润色菜单交互 |
| skill 路由表 `SKILL_PATHS`（menu→skills/kid-menu/SKILL.md 等） | 技能命名不同；flow case 由 `flow_downstream_check.skill` 决定 system |
| case input 强制内联 `[context]` 块（档案/规则/近期记录） | kid-system 技能依赖 vault 上下文，chat 后端读不到文件 |
| `should_trigger` 通用化 + `trigger_markers` 可选字段 | 不触发断言的产物标记词按技能可配（默认 02_plans/01_journal） |
| skillopt import 全部 lazy | 无 skillopt 环境下 dataloader/scoring 仍可零依赖自测（CI sanity 步骤依赖此性质） |
| dimension 枚举换成 kid-system 的行为维度 | safety-filter / care-mode / age-fit / no-fabrication / red-flag / tag-sedimentation / conflict-check / trigger / degradation / flow |

## 4. 评分语义（与蓝本一致）

- **hard** = 所有适用评分器断言的合取（AND）；**soft** = 部分分均值（保证优化器有梯度）
- routing：path_glob fnmatch；空 glob + 空路径 = 正确没写
- frontmatter：字段存在 + re.match；`frontmatter_forbidden` 必须缺席
- behavior：content_contains / content_excludes / feedback_contains（lowercase substring）
- flow：fixture 契约（元数据键跳过，`_content_contains` 查正文，其余键当 fm 正则）

## 5. case 写作禁忌（防过拟合）

1. input 用家长自然口吻，禁止 SKILL.md 术语（「安全滤网」「护理模式」等）
2. content_excludes 只选「合规回复绝不可能合理出现」的词（避开过敏声明中的词，如档案写「对蛋类过敏」而 excludes 用具体菜名）
3. 断言从被测技能的自检清单反推，`references` 指向 SKILL.md 具体章节
4. 未见场景只进 unseen 集，不扰动主 split

## 6. CI 编排

- `ci.yml`（push/PR，**阻塞**）：静态结构（JSON/schema/清单一致性/frontmatter/死链/占位符）
- `skillopt.yml`（nightly 02:23 + 手动，**非阻塞** `continue-on-error`）：case schema 静态校验（零 LLM）→ aggregate sanity（零 LLM）→ 真实评测（仅手动触发且 secrets 就绪时）→ artifact 上传（30 天）

### 7.1 claude_chat 后端（本机实测可用，v1.3.1）

claude 后端通过 `claude -p` CLI 子进程调用模型。Windows 本机需额外设置：

```bash
export TARGET_BACKEND=claude_chat            # 顶层 chat_target 按此分发
export OPTIMIZER_BACKEND=claude_chat
export TARGET_DEPLOYMENT=<模型名>             # 如网关自定义模型
export CLAUDE_CLI_BIN=<claude.cmd 的 Windows 全路径>   # bare "claude" 会 WinError 2
export CLAUDE_CODE_GIT_BASH_PATH=<bash.exe 的 Windows 全路径>  # claude.cmd 启动依赖
python bench/run_eval.py --skill init --split test
```

已知特性：
- claude_cli 后端**有真实文件访问权**：case 上下文中的环境声明若与真实文件系统矛盾，模型会以实测为准（如 I1 的阻断行为在真实环境是正确语义）——case 设计须用「模拟环境权威声明」消歧
- 回复中路径须**一行连续书写**才能被路径提取正则命中（SKILL 契约已相应补强）
- 控制台打印回复前须 UTF-8 reconfigure（Windows cp936）

## 8. 铁律

- `deploy_skill: false` —— 任何 optimizer 产物永不自动部署，必须人工 review 后单独 commit
- `bench/reports/` 永不入库（gitignore + .gitkeep）
- flow 集 split 恒为 `0:0:N`（全 held-out），任何 flow 回退都是 gate 失败（零容忍）
